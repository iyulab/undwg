# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `detect_version`: the version a DWG file declares in its first six bytes. R2000 to R2018 (`AC1015` to `AC1032`) are read; R13 and R14 are named and refused; anything else is an error that shows the bytes it found.
- A corpus test that checks, file by file, that the answer agrees with the six bytes.
- `read_header`: the file header. For R2000 the section-locator list, with its 16-bit checksum and closing sentinel checked; for R2004, R2010, R2013 and R2018 the masked header block is unmasked, its identifier and 32-bit checksum checked, and the positions of the page map and section map returned. R2007 is an explicit "not read yet" error. A checksum, identifier or sentinel that does not match is an error that says what was found.
- A corpus test over real files: every R2000 to R2018 header passes its checksum and its stored offsets lie inside the file.
- `read_directory`, `read_data_page`, `read_section`: for R2004, R2010, R2013 and R2018, the section page map and the section map (compressed system pages, checksummed), data pages (masked 32-byte header, header and payload checksums), and a section assembled from its pages into exactly its stated size. The decompressor refuses a copy from before the start of the output, an opcode the format does not use, and any output length other than the stated one. A section marked encrypted is refused rather than returned.
- `BitReader`: the bit-packed value forms the format uses -- bit, bit triplet, bitshort, bitlong, bitlonglong, bitdouble (with and without a default), raw values at any bit alignment, modular chars and shorts, handle references, object types. Reading past the end of the data and the codes the format marks as unused are errors, never a zero.
- `read_classes`: the class definitions of an R2000, R2004, R2010, R2013 or R2018 file (R2000 does not state how many objects a class holds), with the section's checksum checked and, from R2010, the main stream and the string stream required to meet where they should.
- A corpus test that reads the class definitions of every R2004-family file.
- `read_object_map`, `read_object_frame`: the object map (checksummed blocks of handle and position increments) and the frame of each object -- its size, its type code and its checksum. An entry whose position lies outside the object data is left for the caller to see; an object whose checksum or size does not hold is an error, not a guess.
- A corpus test over the object maps and object frames of real files.
- `read_entity`: the common data every entity has (handle, extended data, graphic flag, colour, linetype scale, line weight, visibility) and the geometry of lines, circles, arcs and points. Any other kind of object is left alone. The object map and the frames now also check that the object found at a position states the handle the map gave it.
- A corpus test that reads every line, circle, arc, point, lightweight polyline, ellipse, solid, 3D face and block insertion of real files.
- `read_entity` reads solids (thickness, elevation, four corners, extrusion) and 3D faces (the first corner whole, the others difference-coded against the one before, and which edges are invisible).
- `read_entity` reads ellipses and elliptical arcs: the centre and the semi-major axis vector (both in world coordinates), the extrusion, the axis ratio and the start and end angles (eccentric anomalies in radians).
- `read_entity` reads block insertions: the insertion point, the scale (stored as all ones, one value with the others defaulting to it, or three values), the rotation, the extrusion and whether attributes follow. The inserted block is named by a handle in the handle stream, which is not read yet.
- `read_entity` reads lightweight polylines: the vertices (the first stored whole, the rest difference-coded against the previous one), the bulge and width of each segment, the constant width, the closed flag, elevation, thickness and normal. A count the stream states is bounded by the bits left, so damaged data cannot allocate.
- `read_entity` also reads the handle stream of an entity: its `references` (owner, persistent reactors, extension dictionary, layer, and the linetype, material and plot style when the entity has its own) with every relative handle resolved to an absolute one, and for a block insertion the block header it inserts, its attributes and its sequence end. `BitReader`'s `HandleRef::resolve` does the resolving.
- `read_entity` now checks that an entity's fields fill its main data stream exactly and that its handles reach the end of the object's data; an entity that is read wrongly stops being read quietly. For R2007 and later the string stream that precedes the handles is located (its size field may continue in a second short).
- `read_entity` reads text: the insertion and alignment points, elevation, extrusion, thickness, oblique angle, rotation, height, width factor, justification, generation flags, the style reference and the value (`TextValue`: bytes in the drawing's code page before R2007, UTF-16 from R2007, where it is read from the string stream). `BitReader::text` reads the two forms.
- `read_block_name`: the name of a block header, so that the block a block insertion inserts can be named.
- `read_entity` reads attributes and attribute definitions: a text with a tag, flags (invisible, constant, verify, preset), whether the position is locked (R2010 and later) and, for a definition, the prompt. The layout from R2010 on -- a byte after the text, the attribute type before the tag from R2018, one more byte after the lock flag in a definition -- is what real files show; a multiline attribute (an embedded multiline text) is refused as unsupported.
- `read_entity` reads multiline texts (MTEXT): insertion point, extrusion, x axis, rectangle and extents sizes, character height, attachment, drawing direction, line spacing and the text with its formatting codes as stored; from R2018 the redundant fields and the column data of a text that is not annotative are read too.
- `read_entity` reads dimensions of all seven kinds (ordinate, linear, aligned, three-point and two-line angular, radius, diameter): the data every dimension has -- the text middle, the typed text, the rotations, the insertion scale of the block that draws it, the line spacing, the measurement -- and the points of the kind, named by their DXF group numbers; the handles of the dimension style and of the anonymous block. `read_dimstyle_name` reads the name of a dimension style.
- `read_entity` reads splines: the degree, the knots, the control points with their weights and the closed and periodic flags, or the fit points with the tolerance and the end tangents. Up to R2010 the stated scenario tells which of the two the file gives; from R2013 the fit-point flag does, because real files state a fit-point spline with scenario 1.
- `read_entity` reads 2D and 3D polylines and their vertices: a polyline's flags, curve type, default widths, thickness, elevation and extrusion and the handles of the vertices it owns (R2000 names the first and the last, later versions all of them) and of its sequence end; a 2D vertex's flags, point, widths (a negative start width states both), bulge, identifier and tangent; a 3D vertex's flags and point.
- `read_entity` reads rays, infinite lines, traces and geometric tolerances: a ray's or infinite line's point and direction, a trace's corners (the same form as a solid), a tolerance's insertion point, direction, extrusion and text, with the handle of its dimension style.
- `read_entity_with_classes` reads hatches -- the boundary paths (polylines, and edges: lines, circular and elliptical arcs, splines), the solid or pattern fill with its pattern lines and dashes, the style, the seed points, the gradient flag from R2004 and the handles of the boundary objects. A hatch has the fixed type code 78 in R2000 and is an object of a class in later versions, so the class table of the file is passed in. `read_entity` is the same without classes.
- `HeaderR2000::section`: the bytes of a section the R2000 locator list names. The class definitions, the object map and the object frames of R2000 files are read with the same readers as later versions, from those bytes and from the file itself.
- A corpus test that reads the table of contents of every R2004-family file, checks every listed page, assembles every section, and checks that the header and class sections open with their documented sentinels.
- `read_layer`: a layer table entry -- its name, flags (frozen, off, frozen in new viewports, locked, plot, and the line weight code in bits 5 to 9), colour (a colour number or a true colour; R2004 and later state it as a long whose top byte names the way) and the handles of its owner, external reference block, plot style, material and linetype. The main stream must end exactly where the colour does. Before R2007 the name is followed by a bit, a short and a bit; from R2007 by one short.
- `read_linetype_name`: the name of a linetype, so that the linetype an entity or a layer points to can be named.
- `CommonEntity::rgb` and `CommonEntity::transparency`: the true colour and the transparency an entity states, which were skipped until now.
- The corpus test checks that every layer an entity names has an entry and that a layer's owner and linetype are objects of the right kind.
- `read_block_header`: a block header -- its name, the anonymous, attribute-definition, external-reference and overlay flags, the base point, the external reference path and the description. The main stream must end exactly where the fields do; an external reference states no count of owned objects. The handles after the owner are not read yet.
- `read_entity` reads viewports (type 34): the window (centre, width, height), the view (target, direction, twist, height, centre, lens length, clip distances), snap and grid, the status flags, the plot style sheet name, the viewport's UCS, the shade plot mode (R2004 and later) and, from R2007, the grid major count and the default lighting fields; the handle stream gives the frozen layers, the clip boundary and the named and base UCS. The handle stream has a base UCS handle from R2000 on and a shade plot handle on every version from R2007.
- `read_entity_with_classes` reads raster images: the insertion point, the pixel vectors, the size, the display flags, brightness, contrast, fade and the clip boundary in pixel coordinates (two corners for a rectangle), with the image definition named by handle.
- `read_image_definition`: an image definition (class `IMAGEDEF`): the file path, the size in pixels, the size of a pixel, whether it is loaded and the resolution unit.
- The size of a stored graphic in the common data of an entity is read as a bitlonglong with a plain three-bit length (R2010 and later). The specification points to the bit triplet for the length; files with a graphic of 164 bytes show `001` and one byte. Entities that carry a graphic (raster images with a clip boundary) were unreadable from R2010 before.
- `read_entity` reads leaders (R2000 and R2004): the annotation type, the path type, the vertices, the leader plane (origin, extrusion, x direction), the offset to a block insertion point, the end point projection, the size of the text box, the hook line and arrowhead flags, and the annotation and dimension style by handle. A leader of R2010 or later is refused with an error that says so: in the files seen the part after the vertices is shorter than the fields the specification lists.
- `read_entity` reads multilines: the scale, the justification, the base point, the extrusion, whether the path is open or closed, and each vertex with the direction of its segment, its miter direction and, for every line of the style, the segment and area fill parameters; the style is named by handle. `read_mlinestyle_name` names a multiline style.
